# M2 縦切り 1 面 — 起動ロゴから 2 面の空中戦まで暗転なし

指示書 §9 M2「起動ロゴ → タイトル → 出撃 → 1 面全区間 → 2 面空中戦まで、暗転なしで通る（シームレス接続の実証）」。
openMSX（`My_FS-A1ST_512K`）で、起動から 2 面の空中戦まで一度も表示を消さず、遅れたフレーム 0 で通ることを
自動検証で確かめた。実機は未確認。

## 縦に長い世界と表示リング

縦の座標 s を「都市の画面の行」に揃えた（0 = 雲の底、158 = 歩道）。空中戦の空と雲は s = -188..-1。表示リング
（ページ 0|1、512x256）の行は `(188 + s) & 255`、R#23 は `(188 + 画面の上端の s) & 255`。

- 画面に出るのは 188 行なので、リングの残り 68 行と画面から出た行を、次に見える s の内容へ描き替えながら進む。
  8 行ごとのブロック（32 個）に「今どの s を持っているか」を持ち、進む向きに 60 行先までの窓で欲しい s と違って
  いて、かつ画面に出ていないブロックを描き替える（`stage.c`）。
- 都市は短冊からの HMMM、高い空は HMMV と星。空中戦の空と雲は起動時の絵をそのまま使う。
- リングの 184..191 行（s = -4..3）は、近い雲の底と都市の雲の底の上端がどちらも色 6 だけなので描き替えない。
- ラスターは s の帯の境目を「画面の行 = s - 上端」に置く。帯は s の順 = 画面の行の順に出てくるので並べ替えない。
  画面より上に出た境目は 0 行の項目にまとめる。

## 分かったこと（エンジンの設計に効くもの）

1. **HMMM は 1 バイト約 5us（表示中・スプライトあり）**。8x188 の列 1 本で 4ms かかる。VDP のコマンドは「次の 1 つ」
   ずつに分け、時間の予算の間だけ続けて出し、最後のコマンドは待たずにフレームをまたがせる。
2. **項目どうしが近いと R#19 を仕込む前に行が過ぎ、そのフレームの残りのラスターが全部消える**。割込みは R#19 の
   3 ライン後あたりで来て、適用に 2〜3 ラインかかる。ISR は 6 ライン未満の次の項目を待たずに続けて適用し、
   リストを組む側も 6 ライン以上あける。
3. **GRAPHIC7 の表示中に VRAM を書くと、書き込みが別の場所へ化ける**（M0-4）。分割を解いたフレームも、表示中の
   リストはまだ前のフレームのもので 244 行から SCREEN 12 になる。「表示中のリストを作ったときの分割」を覚えて待つ。
4. **ヘッダの `static const` の表は、取り込んだファイルの数だけ複製される**（スプライトの絵 800B × 6）。常駐が 32KB を
   超えて気付いた。表は 1 つのファイルだけに置く。
5. **R#23 を帯で変えると、その帯のスプライトの Y もずれる**（スプライトは R#23 を足した位置で比べられる）。HUD 帯は
   自前の属性表、面の開始表示の帯はプレイエリアと同じ R#23 で済ませた。
6. ページ 3 の 192 行から先はスプライトの表。タイトルの素材の読み込みで 211 行まで消していて、上の帯の色表が 0 に
   なり、敵が 1 フレームおきに黒く点滅した（属性表の二重化の片方だけ）。
7. 雲の描き直しを C で 1 画素ずつ求めると 1 バイト 54us かかり、起動と再開で 3 秒黒い画面が続いた。種類の表と
   asm の内側のループで約 1 秒。

## 指示書との差

- タイトルの地平線の帯は 56 行（指示書は 64 行）。分割の境目の項目がロゴの 64 行の項目と重なるため。
- 出撃のカタパルト・オーケストラヒット・音声、ロゴの下の回転する∞（ROTOR）は M3 / M7。
- 降下の縦スクロールは画面全体で 1 つ（雲の層ごとの速さの差は横だけ）。都市後半の遠景の視差は M3 以降。
- 面の開始表示の帯は本当の透過ではなく、帯の地をその高さの空の色にしている。
- ゲームオーバーからの再開は表示を止めて約 1 秒（ネームエントリーと巻き戻しは M8）。
