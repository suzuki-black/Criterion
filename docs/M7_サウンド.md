# M7 サウンド — FM + リズム + PSG の BGM、PCM、効果音、ドライバの拡張

指示書 §9 M7「全 BGM、PCM、効果音、ドライバ拡張機能」。完了条件「全場面で曲と PCM が鳴る」を openMSX
（`My_FS-A1ST_512K`）で確かめた。起動から 1 周して 2 周目に入るまで、場面ごとに決めた曲が鳴り、声の PCM が鳴る
（`tools/test/run_game_m7.sh`）。**曲と音声は作業環境で耳では確かめていない**（docs/TODO.md）。実機は未確認。

## 置き場所（常駐がいっぱい）

常駐（ページ 1-2、32KB）の残りは M6 の時点で 3KB ほどしかなく、ドライバの C 版（4.4KB）が入らなかった。

- シーケンサの中核を asm にした（4.4KB → 2.9KB、速さも上がった）。
- 選曲・効果音・PCM を鳴らす側を CODE0（ページ 0 の RAM）の `music.c` に置いた。CODE0 を広げるため、オーバレイの先頭を
  0x0A00 → 0x1000 へずらした（窓は 10KB。最大の s1 が 9.9KB）。
- 本体が使っていない PCM 方式 B（`pcmb.c`、M0 の比較用）を本体のリンクから外した。
- 曲を読む間は ROM の曲のバンクをページ 2 に出すので、`snd.c` はページ 1 に置く（Makefile が検査）。

## 分かったこと（エンジンの設計に効くもの）

1. **PCM の刻みを R#19 の値で数えると、帯で R#23 が変わったところで鎖が切れる**。openMSX の走査線割込みは表示ライン
   (R#19 − R#23) ちょうどで来る。刻みは表示ラインで数え、仕込むときに R#23 を足す（`ras_tl`）。R#23 を変える項目を
   適用した後は 2 ライン先の刻みが過ぎていることがあるので、1 つ先を仕込み、飛ばしたサンプルはその場で出す。
2. **刻み方式の最中に本体が R#1 を書くと、VBLANK 割込みが戻る**（表示の on/off など）。その割込みが項目方式の R#19 を
   仕込み、刻みが 1 フレームに 1 つになった。刻み方式の間の VBLANK 割込みは IE0 を止め直すだけにする。
3. **刻み方式の終わりは割込みの中の刻み 212 で**。本体からすぐ VBLANK 割込みを戻すと、そのフレームの JIFFY を刻み 212 と
   VBLANK で 2 回数え、遅れたフレームになった。
4. **曲データのバンクの出し入れは 1 回約 50us**（スロットとマッパーへの書き込み）。待ちの減算はバンクの外でして、
   命令を読むフレームだけ出す。
5. **PCM（刻み方式）は CPU の約 4 割を使う**。ゲームの重い場面では足りないので、曲の中のオケヒは余裕のあるときだけ、
   声は落ち着いた場面まで待ち、遅れたらその場で止める。鳴っている間は論理を 1 フレームおきにし、締め切り（`g_frame_t0`
   からのライン数）を 64 ライン前倒しにする。
6. **処理落ちのフレームは自機の弾も止める**。当たり判定は処理落ちのフレームに走らないので、弾だけ進むと 2 フレームで
   小さな的をすり抜けた（TOLERANCE の砲台、試験の KILOGRAM）。音で処理落ちが増えて目立った。
7. 音の処理はフレームの頭で、前のフレームに空きが無ければ先送りする。フレームの終わりに回すと、タイトルなど締め切りの
   無い場面でかえって遅れた。

## 指示書との差

- 曲は各 8〜16 小節のループ。タイトル曲の「帯が組み上がるごとに低音」は時間で積む。ほかの未実装は docs/TODO.md。
- PCM は重い場面では鳴らない（上の 5）。
- 7 面の試験の声（CALIBRATION）は、1 つ目は試験の入りで、2 つ目からは前の試験のボスを倒した直後（次の試験の予告）に鳴らす。
  8 面の声（UNMEASURABLE）は空中戦ではなく、7 面の後の STAGE 8 の表示の間に。

## 検証

- `tools/test/run_game_m7.sh <作業ディレクトリ>`: `run_game_m6.sh` の通し（1 周 + 2 周目の入り）に音の確認を足したもの。
  MSX-MUSIC の検出、場面ごとの曲（23 か所）、声の PCM（ロゴ・出撃・警告は必ず。試験と 8 面は鳴ったか捨てた記録があるか）、D/A への書き込み、曲を鳴らす区間で発音が進むこと、
  刻みの鎖の張り直し 0。遅れたフレームは PCM を止めた回数 + 3 まで許す。
- `run_game_m1〜m6.sh` は PCM を切って流す（BGM は鳴らす）。遅れは 1 周で 2 フレームまで許す（BGM のドライバが最も重い場面の
  山に重なったときの 1 フレーム。docs/TODO.md）。M0 の 4 本も通る。
- 試験 2 の KILOGRAM は、弱点の出る時間が乱数の重力しだいで、自動操作では時間切れになることがあった（体力 8 で残る）。
  LIBRA と同じく LIMIT BREAK の傷を 8 秒ごとに入れる（m6・m7）。
- ★**検証スクリプトは判定がエラーでも必ず終わらせる**（`safe_finish`、エミュレータの時刻で 1500 秒）。判定の Tcl の誤り
  （`$nl(...)` が配列として読まれた）で `exit` に届かず、throttle off のまま 2 周目・3 周目と遊び続けた。
- 1 周の通しは重い（m7 は D/A の見張りで実時間 20 分以上）。原因の調査は、通しを 1 回流して `savestate` で場面の手前を
  保存し、そこから短く回す。★保存した状態には RAM に写したコードも入るので、本体やそのとき読み込まれているオーバレイを
  変えたら使えない。
