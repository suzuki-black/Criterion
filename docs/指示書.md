# Criterion — 開発指示書（MSX turboR 専用 横スクロールシューティング）

> ワークスペース名：`Criterion`
> 対象機種：MSX turboR 専用（FS-A1ST / FS-A1GT、R800 DRAM モード前提）
> 形態：ASCII8 メガROM（1MB 推奨、最低 512KB）
> 系譜：`ZeroNoHoukouR`（真 零の咆哮）のエンジン・知見を横スクロール向けに発展させる
> 版：設計指示書 v0.1（2026-10-02）

---

## 0. この指示書の立ち位置

本作のコンセプトは一行で言えば次のとおりです。

**「1990年当時のコナミ MSX 開発陣が、プロデューサー不在のまま（＝バランス調整という制動なしで）、技術力だけを武器に turboR 専用の横シューを作っていたら、おそらくこうなっていた」**

ゲーム性でスペースマンボウや MSX 版グラディウス2に勝つことは目標にしません。目標は、**画面と音のすべての瞬間に「この機械でこれをやるのか」という驚きを置くこと**です。以下の設計思想を全工程の判断基準とします。

| 原則 | 内容 |
|---|---|
| 一面一芸 | 各ステージに「その面でしか見せない主役の技」を必ず一つ置く。同じ技を二度主役にしない（7面のボスオンパレードは例外で、過去の技の“再校正版”として再登場させる） |
| 止めない | ゲームはタイトルからエンディングまで一本の連続飛行として作る。暗転・画面消去・「STAGE 2」だけの静止画面は禁止 |
| 隠さない | 処理落ちは計測して記録する。消せない場合は「重い場面ほど派手」に寄せ、当時らしさとして受け入れる |
| ハードを語らせる | V9958 のレジスタ（R#23/R#26/R#27/R#25/R#19）、R800 の乗算命令、turboR の PCM を、演出の“理由”として使う。使う理由のない技は入れない |
| 遊べること | バランス調整はしないが、1周クリア可能であることだけは保証する（検証はセーブステート併用で可） |

## 1. ストーリー

### 1.1 あらすじ（ゲーム内マニュアル・アトラクト用）

西暦 2xxx 年。外宇宙から、それは「測りに」来た。

自らを **Criterion（クライテリオン）** と名乗るその存在は、物事を判断するための唯一絶対の尺度を自負する機械知性だった。彼らは銀河を巡り、出会った文明を自らの目盛りに当てて測る。基準に収まるものは「規格内」として標本化され、収まらないものは「規格外」として**校正**——すなわち削り取られる。

地球文明に下された判定は「規格外」。

測定艦隊は大気圏へ降下し、都市には無数の小型測定機械が降り立った。人類の兵器はことごとく「既知の数値」として読み取られ、発射される前に無力化されていく。

地球防衛軍（劇中英語表記：**TDF / Terran Defense Force**）に残された最後の手段は、ただ一機の試作戦闘機だった。あらゆる計測値を意図的に“確定させない”よう設計された、測定不能の機体。

その名は **Infinitas（インフィニタス）**——ラテン語で「無限」。

規格に収まらないものは、測れない。測れないものは、裁けない。
傲慢な絶対尺度に挑む、ただ一機の孤独な戦いが始まる。

### 1.2 敵の設定（デザイン統一のための背景）

Criterion の兵器はすべて**計測器・度量衡器**をモチーフとします。ノギス、分度器、メトロノーム、下げ振り、水準器、砂時計、日時計、天秤、そして最終的には「原器」。敵の外装には必ず**目盛り（グラデュエーション）**の意匠を入れ、撃破時には目盛りが崩れて飛び散ることで統一感を出します。

敵の音声・文字表示は無機質な判定文で統一します（例：`SUBJECT: INFINITAS ／ STATUS: UNMEASURABLE`）。物語の進行に合わせて、この判定文が少しずつ崩れていく（7面で `TOLERANCE EXCEEDED`、8面で `VALUE OUT OF RANGE`、最期に `∞`）のが、台詞のない本作のドラマの骨格です。

### 1.3 名称に関する注意

「地球防衛軍」という日本語は他社のゲームシリーズ名と重なるため、**画面上の表記は TDF（Terran Defense Force）に統一**し、和文は説明書きの中でのみ「地球防衛軍」と書きます。

## 2. 自機とパワーアップシステム

### 2.1 自機 Infinitas

| 項目 | 仕様 |
|---|---|
| サイズ | 24×12 ドット相当（スプライト 16×16 ×2枚、OR 合成で 3〜4 色） |
| 当たり判定 | 中心 4×2 ドット（見た目より小さく。当時のコナミ流） |
| 操作 | 8方向移動、A：ショット（押しっぱなしで連射）、B：パワーアップ確定 |
| 特殊 | 速度段階に応じて機体後方に残像（ソフトウェアスプライト）が伸びる |

### 2.2 グラディウス方式についての判断

ゲームの**仕組み（ルール）そのもの**は一般に著作権の保護対象ではないとされ、「アイテムを取ってゲージを進め、好きなところで確定する」型のシステムは多くの後発作品にも見られます。ただし、**ゲージの見た目、項目の並び順と名称（SPEED UP / MISSILE / DOUBLE / LASER / OPTION / ?）、カプセルの外見と効果音**まで揃えると、表現の模倣や商品表示の混同と受け取られる余地が出てきます。私は弁護士ではないので断定はできませんが、本作は趣味の公開作品であっても「グラディウスの手触り」は残しつつ、**見た目・名称・並び・遷移の仕方をすべて独自にする**方針を取ります。結果として、次の独自システムを採用します。

### 2.3 独自システム「∞ゲージ（レムニスケート・ゲージ）」

画面下 HUD に、**∞（8の字）の形をした軌道**を表示します。軌道上には 7 つのノードがあり、カーソルが光点として軌道を巡ります。

```
        [THRUST]               [DROP]
     /           \           /         \
 [AEGIS]          (∞)          [SPLIT]
     \           /           \         /
        [ECHO]                 [RAY]
```

**カーソルの進み方**：敵編隊を全滅させると出る結晶 **Quanta（クオンタ）** を取るたびに、カーソルが一つ進みます。進路は∞の字を一筆書きでなぞる順で、

`∞ → THRUST → ECHO → AEGIS → ∞ → DROP → SPLIT → RAY → ∞ → …`

と巡ります。中心ノード（∞）を一周に二回通るのが特徴で、左ループは「機体系（BODY）」、右ループは「兵装系（ARMS）」です。B ボタンで現在ノードを確定すると、カーソルは中心に戻ります。

| ノード | 系統 | 効果 | 上限 |
|---|---|---|---|
| THRUST | 機体 | 移動速度 1 段階アップ。段階ごとに残像が伸びる | 5 段階 |
| ECHO | 機体 | 追従機「エコー」を 1 機追加。自機の過去位置をなぞり、自機と同じ弾を撃つ。**小型の敵弾を 1 発吸収できる**（吸収後 3 秒点滅で再吸収不可） | 4 機 |
| AEGIS | 機体 | 1 回目：前面に目盛り状の防壁（耐久 8）。2 回目以降：防壁を全周リング化（耐久 4、回転表示） | 前面／全周 |
| DROP | 兵装 | 対地爆雷。地形に沿って這い、段差で落ちる。2 回目で上下両方向 | 2 段階 |
| SPLIT | 兵装 | 主砲を前方 3WAY に。2 回目で 5WAY 扇。RAY と排他 | 2 段階 |
| RAY | 兵装 | 主砲を貫通レーザーに。2 回目で太さ倍。SPLIT と排他 | 2 段階 |
| ∞（中心） | 特殊 | **LIMIT BREAK**：∞の字の衝撃波が拡大回転しながら画面を一掃し、敵弾消去・雑魚全滅・ボスに大ダメージ。ただし発動後は **THRUST 以外の全強化が 1 段階ずつ下がる** | — |

∞を「最強の切り札だが、引き換えに自分の積み上げを崩す」ものにすることで、グラディウスにはない判断（今ここで崩すか、積み上げを守るか）を生みます。物語上も「測定値を自ら崩して測定を逃れる機体」という設定と一致します。

**レア結晶「Infinity Shard（金）」**：ボス撃破時のみ出現。取るとカーソルが即座に中心ノードへ飛ぶ。

**被弾時**：残機 −1、強化はすべて失うが、その場に Quanta を 3 個散らす（重力面では落下する）。

### 2.4 HUD の技術的見どころ

∞ゲージは HUD 帯（SCREEN 5 の下部 24 ライン）に描画し、カーソル光点はスプライト、確定時には∞の形そのものが拡大回転して画面中央に飛び出す演出（回転拡縮エンジン ROTOR を使用）を入れます。HUD 帯はラスター分割でスクロールさせない固定帯とします。

## 4. シーン構成（シームレス設計）

### 4.1 全体の流れ

本作は**タイトルからエンディングまで一本のフィルム**として作ります。シーンの切り替えは「画面を消して次を出す」のではなく、「同じ世界の上に重なる」か「世界がそのまま次の場所へ流れていく」かのどちらかで行います。

```
[電源ON] → [ロゴ] → [タイトル] ⇄ [デモプレイ] ⇄ [ランキング]
                         │
                    PUSH SPACE
                         ↓
                    [出撃シーン] → STAGE1 空中戦 → 本体 → 中ボス → ボス
                         → (飛行継続) → STAGE2 空中戦 → … → STAGE8 ボス
                         → [脱出] → [エンディング] → [2周目へ]
         [ゲームオーバー] → [ネームエントリー] → [巻き戻し] → [タイトル]
```

### 4.2 各シーンの指示

**起動ロゴ**：黒画面に「TDF」の小さな紋章が、走査線 1 本ずつ描き込まれるように出現（ラスターでパレットを帯ごとに点灯）。PCM で短い電子音声 `SYSTEM ONLINE`。2 秒。

**タイトル**：画面上部 64 ラインを **SCREEN 12（YJK 自然画）**、下部を SCREEN 5 に分割。上部には夜明けの地球の地平線（自然画、ゆっくり横スクロール）、下部は星空の上を Infinitas が飛んでいる。ロゴ「CRITERION」は 8 本のラスター帯に分割して描かれ、**各帯が左右ばらばらの方向から滑り込んで一枚に組み上がる**。組み上がった瞬間に PCM のオーケストラヒット。ロゴの下に回転する∞の紋章（ROTOR）。

**デモプレイ**：タイトルから 15 秒放置で、**画面を切らずに**ロゴが帯ごとにほどけて左右へ飛び去り、そのまま下部の Infinitas が実エンジン上で記録入力に従って戦い始める。デモは 1 面・3 面（高速区間）・4 面（ラスター区間）・5 面（巨大戦艦の接近）の 4 種をローテーション。デモ中も画面上に「DEMONSTRATION」を ROTOR で拡縮しながら表示。

**ランキング**：デモ終了時、自機が画面奥へ縮小して消え（拡縮）、背景は流れたまま、上下からスコア表がラスター帯でスライドイン。上位 10 名を表示し、1 位の行だけパレットサイクルで虹色に光る。終わると帯が閉じ、再びロゴが組み上がってタイトルへ。

**出撃シーン（ゲーム開始）**：SPACE を押すと PCM 音声 `INFINITAS, LAUNCH`。ロゴは拡大しながら砕け（拡大スプライトの破片）、カメラ（スクロール）は加速。地上基地のカタパルトから Infinitas が射出され、背景がそのまま 1 面の夕焼け空へと流れていく。**この間にプレイヤーは既に操作可能**。

**ステージ開始表示**：画面を止めない。HUD 帯の上に 16 ラインの透過帯を一時的に作り、`STAGE 2 ／ GRAVITY WELL` を左から右へスライドさせ、2 秒で HUD 帯へ吸い込ませる。

**ステージ間の接続**：ボス撃破後、Infinitas はそのまま飛び続け、背景が次ステージの空中戦エリアへ連続的に変化する（例：1 面の都市上空から急上昇 → 縦スクロールで成層圏 → 2 面の軌道上）。空中戦区間は背景を星空・雲などの軽いものにし、**この区間で次ステージの BG データを VRAM の見えない領域へ転送する**（ロード隠しを演出として兼ねる）。

**ゲームオーバー**：最後の残機が爆発した瞬間、スクロールは慣性で減速して停止。BGM は PCM の低いオーケストラヒット 1 発で途切れ、`GAME OVER` の文字が一文字ずつ、遠くから拡大しながら画面に“刻印”される。

**ネームエントリー**：ゲームオーバーの停止画面の上に、**回転する文字盤（ダイヤル）**が出現。A-Z と記号が円周上に並び、左右で文字盤を回して選ぶ（ROTOR による回転、計測器モチーフの文字盤）。入力欄は 3 文字。背景では、Criterion の測定ビームが自機の残骸を走査している演出が続く。

**巻き戻し**：ネームエントリー終了後、画面全体が**高速逆スクロール**で、これまで飛んできたステージを逆再生するように巻き戻り（背景 BG を逆方向に高速で流し、スキャンラインノイズを帯状に挿入）、タイトルの地球の地平線に戻る。「Criterion が記録をリセットした」ことの表現。

**エンディング**：8 面ボス撃破 → 脱出（高速スクロール）→ 母艦崩壊を背景に宇宙へ抜ける → 地球を見下ろす SCREEN 12 の自然画帯 → スタッフロールは画面を止めずに、背景を流しながら下から上へ（R#23 縦スクロール）。最後に `SUBJECT: INFINITAS ／ STATUS: ∞` と表示され、そのまま 2 周目の出撃シーンへ。

**2 周目**：敵弾速度と量が増え、ボスオンパレード面の全ボスが「再校正版」の動きになる。当時のアーケードの流儀として周回はループ制。

### 4.3 隠し要素（コナミ伝統）

タイトルで特定のキー入力により「SOUND TEST」と「VDP MONITOR」（現在のラスターリストと各帯の処理時間を枠線色で表示するデバッグ画面）を開放。技術力を売りにする作品なので、**負荷可視化そのものを隠し要素として見せる**。

## 5. ステージ構成（全 8 面）

### 5.0 一覧と必須要素の割り当て

| 面 | タイトル | 主役の技 | 必須要素 |
|---|---|---|---|
| 1 | 黄昏の降下 / TWILIGHT DESCENT | BG 直描きの機械兵の群れ（スプライトを使わない大量表示） | 原案：地上戦 |
| 2 | 重力井戸 / GRAVITY WELL | 重力場＋ラスターによる重力レンズ歪み | 原案：重力面 |
| 3 | 臨界加速 / OVERDRIVE CORRIDOR | 高速スクロール・急停止・逆スクロール | **高速＋停止・逆スクロール面** |
| 4 | 層流 / STRATA | 多段ラスタースクロールと帯分割の巨大キャラ | **ラスタースクロール面** |
| 5 | 規格戦艦ノルム / DREADNOUGHT "NORM" | 数画面にわたる巨大戦艦と、拡大による接近演出 | **巨大戦艦面** |
| 6 | 日時計要塞 / GNOMON CITADEL | 画面上下のスクリーンモード分割＋大型回転 | — |

| 8 | 原器 / THE PROTOTYPE | 全技術の総動員、多形態ラスボス | 最終面 |

各面は「空中戦 → ステージ本体 →（中ボス）→ ステージ本体後半 → ボス」の構成とします。以下の記述で、各区間の長さは標準スクロール速度（1 ドット/フレーム）換算の目安です。

---

### 5.1 STAGE 1「黄昏の降下 / TWILIGHT DESCENT」

**情景**：Criterion に占領された地球の都市。夕焼けの雲海から雲を突き抜けて降下すると、眼下の廃墟を無数の小さな機械兵が埋め尽くしている。

**主役の技**：4×4 ドットの機械兵「Pawn」を**スプライトを一切使わずに BG へ直接描画**し、最大 64 体を同時に動かす。スプライト 32 枚・1 ライン 8 枚の制限とは無関係に“群れ”を見せることで、オープニングから「この作品は数の制限を無視する」と宣言する。

| 区間 | 長さ | 内容 | 技術 |
|---|---|---|---|
| 空中戦 | 約 2 画面 | 夕焼けの雲海上空。Tick/Tock 編隊、Notch 突撃 | 空のグラデーションは帯ごとのパレット書き換え（ラスター 6 帯）。雲は 3 層の多重スクロール |
| 降下 | 約 1 画面 | 雲を突き抜けて斜めに降下 | **R#23 縦スクロール**と横スクロールの同時進行。雲層の帯ごとに速度差 |

| 6 | CALIBRATION TEST 06 | GNOMON | 針が 2 本（長針と短針）になる |

各試験の間には短い通路（約 1 画面）を挟み、試験開始時には画面上部に `CALIBRATION TEST 0x ／ SUBJECT: INFINITAS` と表示する。試験に合格（ボス撃破）するたびに判定文が `RESULT: OUT OF TOLERANCE` と少しずつ赤く崩れていく。

**最終試験ボス LIBRA**：巨大な天秤。左の皿に Infinitas の“測定値”（自機の現在の強化状態を視覚化したアイコン群）が載せられ、右の皿に Criterion の分銅が載る。**自機の強化段階が高いほど天秤が自機側に傾き、ボスの攻撃が激しくなる**。ここで∞の LIMIT BREAK を使って自らの強化を崩すと天秤が跳ね上がり、分銅が落下して弱点が露出する。∞ゲージの「崩すことで測定を逃れる」仕組みが、物語と攻略の両方で意味を持つ場面。

**接続**：LIBRA が壊れると白い測定空間が黒く反転し、母艦の最深部へ続く縦穴が開く。

### 5.8 STAGE 8「原器 / THE PROTOTYPE」

**情景**：Criterion の中枢。かつて地球にも存在した度量衡原器のように、二重のガラス鐘に守られた一本の金属棒「原器」が、絶対尺度そのものとして浮かんでいる。

**主役の技**：**全技術の総動員**。縦横の任意スクロール、多段ラスター、モード分割、回転拡縮、スプライト多重化、PCM 音声をすべて使う。

| 区間 | 長さ | 内容 | 技術 |
|---|---|---|---|
| 空中戦 | 約 3 画面 | 最終防衛線。これまでの全雑魚が編隊で出現 | 全種のスプライト多重化。画面内同時 48 枚以上を目標 |
| 縦穴 | 約 4 画面分 | 母艦の縦穴を**下へ**降りる（横スクロールが止まり、縦スクロールに切り替わる）。その後、横穴へ | R#23 縦スクロールと R#26/27 横スクロールの切り替え・併用 |
| 歪曲回廊 | 約 5 画面 | Criterion が Infinitas を測定しようとして失敗し、空間そのものが歪む。床と天井が波打ち、画面全体がうねる | 全帯ラスター（R#27 と R#23 を帯ごとに正弦波で変調） |
| 中ボス | — | **TOLERANCE** | 下記 |
| 中枢 | 約 3 画面 | 原器の間。巨大なガラス鐘が見えてくる | ガラス鐘はパレットのハイライトで透明感を表現 |
| ラスボス | — | **PROTOTYPE ZERO** | 下記 |
| 脱出 | 約 10 画面 | 母艦崩壊。最高速スクロールで脱出 | 3 面の高速スクロール技術を再使用（ただし崩落する破片が全帯で降る） |

**中ボス TOLERANCE（許容差）**：上下二本の“限界線”として現れる敵。画面上端と下端から、目盛りの付いた二本の巨大なバー（BG）が迫ってきて、自機の移動可能範囲を狭めていく。バーに付いた砲台を破壊すると、その分だけバーが押し戻される。

**ラスボス PROTOTYPE ZERO（3 形態）**：

第 1 形態「二重の鐘」：原器を守る二重のガラス鐘。外側の鐘と内側の鐘が**逆方向に回転**し、ガラスの継ぎ目からレーザーが漏れる。鐘はそれぞれ ROTOR で回転させた 96×96 のパーツを上下の帯に分けて表示（スプライト表の帯分割で 64×64 を超える大きさを実現する、『真 零の咆哮』の He 111 の技法の発展）。

第 2 形態「原器」：鐘が割れ、X 字断面の金属棒が姿を現す。棒は**画面いっぱいの大きさで回転・拡縮**しながら（遠ざかり、近づき、自機を叩き潰そうとする）、表面の目盛りから弾を撃つ。最大級の ROTOR 負荷がかかる場面で、30fps 維持を目標とする。

第 3 形態「絶対尺度」：原器が分解し、Criterion の本体である**目盛りのリング**が現れる。画面を取り囲む巨大な円環で、目盛りの一つ一つが砲台。リングは回転しながら縮まり、Infinitas を“測り取ろう”とする。判定文が画面上部で高速に書き換わり（`MEASURING…` → `VALUE: 9999999` → `VALUE OUT OF RANGE` → `∞`）、∞が表示された瞬間にリングが内側から砕け散る。**ラスボスへのとどめは LIMIT BREAK でのみ可能**とする（∞ゲージを中心に合わせる余裕は、このフェーズ中に Infinity Shard が出現して保証する）。

**エンディングへの接続**：リング崩壊 → 母艦崩壊 → 脱出区間（プレイヤー操作あり）→ 宇宙空間へ。以降は 4.2 のエンディング。

### 6.2 ライトモチーフ

全曲を貫く 2 つの動機を作ります。

**Criterion の動機**：同じ音を機械的な均等リズムで刻み続け、最後に半音下へ“判定”を下す音型。「測る」ことの音楽的表現。ボス曲、7 面、ゲームオーバーで使う。

## 8. 技術仕様

### 8.1 前提ハードウェア

| 項目 | 前提 |
|---|---|
| CPU | R800（DRAM モード）。毎フレーム走るコードは RAM に転送して実行する（ROM 実行は Z80 並みに遅くなるため） |
| VDP | V9958。VDP コマンド速度と VRAM アクセス速度は MSX2+ と同じで、R800 の速さは VDP 側の処理には効かない |
| RAM | 最低 256KB（FS-A1ST）を前提に設計。A1GT の 512KB は前提にしない |
| ROM | ASCII8 メガROM 1MB（8Mbit）推奨。プリレンダ素材と PCM のため |
| 開発環境 | SDCC（C ＋ Z80/R800 アセンブラ）、openMSX（C-BIOS turboR 定義）、WebMSX turboR。最終的に実機確認 |

### 8.2 『真 零の咆哮』から継承するもの

常駐エンジンとバンク・オーバレイの規律、RAM 実行のホットコード、シーン FSM、エンティティプール、H.TIMI サウンドドライバ、フレーム途中のスプライト表切り替え、帯ごとの横スクロール、パレットエンジン、1/z 行計算による Mode 7 風処理。これらを**横スクロール前提に再編**します。特に縦スクロール前提だった部分（R#23 主体のスクロール、縦方向の列ストリーミング）は、R#26/R#27 主体＋R#23 補助の構成に書き換えます。

### 8.3 フレーム構造

| タイミング | 処理 |
|---|---|
| VBLANK 割込み | 前フレームで確定したラスターリストの先頭エントリを適用、スプライト属性表の転送（帯ごとに 2〜3 面分）、サウンドドライバ（FM/PSG）、入力読み取り |
| 表示期間（ライン割込み） | ラスターリストに従ってレジスタを書き換え。PCM 方式 C の場合はサンプル出力も兼ねる |
| メインループ | ゲームロジック、敵 AI、ROTOR 計算、GHOST（ソフトウェアスプライト）のコマンド発行、列ストリーミング |

スクロール・ラスター・音は**常に 60Hz**で動かします。ゲームロジックは通常 60fps、重い場面では 30fps に落としても構いません（スクロールが滑らかなまま敵だけ処理落ちする、当時らしい挙動になります）。

### 8.4 ラスターリスト

全ステージのラスター演出を、データ駆動のリストで統一します。リストはダブルバッファとし、メインループが次フレーム分を組み立て、VBLANK で切り替えます。

```c
typedef struct {
    uint8_t  line;        /* 割込みライン（R#23 の補正前の論理ライン） */
    uint8_t  flags;       /* 書き換える項目のビットマスク */
    uint8_t  r26, r27;    /* 横スクロール */
    uint8_t  r23;         /* 縦スクロール（帯内の縦移動） */
    uint8_t  r2;          /* 表示ページ（帯ごとに別ページを見せる） */
    uint8_t  r5, r11;     /* スプライト属性表アドレス（帯ごとの表切り替え） */
    uint8_t  r0, r1, r25; /* モード分割用 */
    uint8_t  r8;          /* SPD ビット（帯単位のスプライト非表示） */
    uint8_t  pal_idx;     /* パレット 1 色の書き換え（0xFF で無し） */
    uint16_t pal_rgb;
} RasterEntry;
```

R#19 に設定するラインは R#23 の値の影響を受けるため、**ハンドラは論理ラインに現在の R#23 値を加算して R#19 を設定**します。帯の境界は 2 ライン以上の余裕を取り、境界ラインは黒い線（雲の縁、装甲の継ぎ目など）でデザイン上隠すことを、背景グラフィック制作の規約とします。1 ライン単位の書き換え（陽炎・重力レンズ）は、その帯の間だけ S#2 の HR ビットをポーリングするループで処理し、その帯の高さぶんのメイン処理時間を予算から差し引きます。

### 8.5 スクロール

**横スクロール**：SCREEN 5 で R#25 の SP2 を有効にし、2 ページ連結の 512×256 を表示面のリングとして使います。表示幅 256 の外側に新しい列を描き込み、R#26/R#27 で表示位置を進めます。左端 8 ドットは R#25 の MSK でマスクします。逆走時は描き込み側を左に切り替えます。8 ドット/フレームの高速時は、毎フレーム 8 ドット幅の列を描き込む必要があるため、背景は 8×8 タイルの組み合わせで構成し、列単位の HMMM 転送で済むようにします。

**縦スクロール**：R#23 による 256 ラインのラップを使います。縦スクロールを使うステージでは、表示ページの 212〜255 ラインも画面に現れるため、**その領域にスプライト表などを置かない**ことに注意します。また、スプライトの Y 座標は R#23 の影響を受けるので、縦スクロールのたびにスプライト座標を補正します。

### 8.6 PCM 再生方式

turboR の PCM には専用の割込みも DMA もなく、BIOS の再生ルーチンは再生中 CPU を占有するため、ゲーム中は自前で D/A ポートへ書き込みます。次の 3 方式を M0 で実測し、決定します。

| 方式 | 内容 | 利点 | 欠点 |
|---|---|---|---|
| A：ラスター相乗り | PCM 発音中だけ、2 ラインごとのライン割込みをラスターリストに追加し、各割込みでサンプル 1 個を出力 | 周期が安定。既存のラスターハンドラと統合できる | 割込み回数が増える（1 フレーム 100 回超）。VBLANK 中の出力の穴埋めが必要 |
| B：タイマーポーリング | S1990 のフリーランタイマ（E6h/E7h）をメインループ各所で確認し、時刻が来ていれば出力 | 割込みを増やさない | 周期が揺れて音が濁る。重い処理の中にポーリングを埋め込む手間 |
| C：混成 | 表示期間は A、VBLANK 期間はタイマーで時刻を測りながら VBLANK ハンドラ内で出力 | 安定性と穴埋めを両立 | 実装が最も複雑 |

本指示書の推奨は C です。PCM は**同時 1 音、優先度制**（音声 ＞ オケヒ ＞ 爆発 ＞ スネア）とし、PCM 発音中のみ割込みを増やすことで、PCM が鳴っていない時間の CPU 負荷をゼロにします。D/A 制御ポート（A5h）の設定ビットは実機資料で確認のうえ実装してください。

### 8.7 スプライト方針

スプライトモード 2 を使い、Infinitas・エコー・主要な敵は 2〜3 枚の OR 合成（CC ビット）で多色化します。画面を 3〜4 の帯に分けて帯ごとにスプライト属性表を切り替え、画面内の同時表示を 48 枚以上にします。ただし 1 ライン 8 枚の制限は回避できないため、横一列に並びやすい編隊は縦にずらした軌道で設計し、重なった場合は優先度をフレームごとにローテーションしてちらつきで見せます。弾幕が濃くなる場面では、敵弾を BG 描画に切り替えます。

### 8.8 ソフトウェアスプライト（GHOST）

**黒基調規約**：プレイエリアの背景はパレット 0（黒）を基調とし、背景の模様は特定のパレット番号群（例：1〜7）に限定します。GHOST は LMMM の透過（TIMP）で描き、消去は描画範囲が黒地なら HMMV で 0 を塗るだけ、模様に掛かる場合は元の BG をソースページから HMMM で復元します。VDP コマンドは RAM 上のキューに積み、CE ビットを見ながら順次発行します。VDP コマンドの処理量が 1 フレームの最大の制約なので、GHOST の総面積は帯域予算表で管理します。

### 8.9 回転拡縮エンジン（ROTOR）

R800 の乗算命令（MULUB / MULUW）で、アフィン変換を固定小数点で計算します。出力先は次の 3 種類です。

| 出力先 | 内容 | 目安 |
|---|---|---|
| スプライトパターン | 16×16 の多色スプライトを、色層ごとに 1bpp で回転生成 | 1 体 64 バイト程度と小さいため、毎フレーム複数体の回転が可能。最も費用対効果が高い |
| BG 小〜中型 | 32×32 〜 64×64 を 4bpp で RAM に生成し、VRAM へ転送 | 64×64 で 2KB。30fps を目標 |
| BG 大型 | 96×96 以上 | リアルタイムは 20fps 程度を上限の目安とし、それ以上はプリレンダのコマと併用。スプライト 2 倍拡大（R#1 の MAG）も組み合わせる |

いずれも数値は M0 で実測して確定させます。

### 8.10 スクリーンモード分割

帯の境界でライン割込みにより R#0 / R#1 / R#25（YJK、YAE）と R#2（パターンネームテーブル）を書き換えます。SCREEN 12 の帯では、スプライトの色が SCREEN 5 の帯と異なる解釈になるため、**R#8 の SPD ビットでその帯のスプライト表示を止める**か、スプライトが帯をまたがない設計にします。境界の 1〜2 ラインは表示が乱れる可能性があるため、黒帯で隠します。使用箇所はタイトル画面、6 面、エンディングに限定し、各エミュレータと実機での見え方を必ず確認します。

### 8.11 VRAM マップ（基本形：SCREEN 5 ＋ SP2）

| アドレス | 用途 |
|---|---|
| 0x00000–0x0FFFF | ページ 0〜1：表示面（512×256 のスクロールリング） |
| 0x10000–0x17FFF | ページ 2：BG タイルのソース、GHOST のソース、ROTOR の出力領域 |
| 0x18000–0x1BFFF | ページ 3 前半：次ステージの BG ソース（空中戦区間で先読み転送） |
| 0x1C000–0x1FFFF | ページ 3 後半：スプライトパターン表、スプライト属性表 × 3〜4 面（帯分割用）、HUD・フォント素材 |

**派生形（帯ごとのページ切り替え）**：4 面 STRATUM や 8 面などでは、ページ 2〜3 を第 2 の表示リングとして使い、ボスの帯だけ R#2 でページ 2〜3 を表示させます。この場合ソース素材は ROM から直接転送する運用に切り替え、ステージごとに VRAM 配置を変えます。ステージ間の VRAM 再配置は、空中戦区間の軽い背景の間に行います。

### 8.12 ROM / RAM

ROM は 1MB の ASCII8 とし、常駐エンジン、ステージごとのバンク、プリレンダ素材、PCM サンプル、楽曲データを配置します。RAM 上には毎フレーム実行されるホットコード（ラスターハンドラ、ROTOR、GHOST のコマンドキュー、PCM 出力、サウンドドライバ）を常駐させ、ボスごとの処理は RAM オーバレイで差し替えます。

### 8.13 計測とデバッグ

各ハンドラの入口と出口で枠線色（R#7）を切り替え、処理時間を画面の枠に可視化します。FPS カウンタ付きのデバッグビルドを用意し、帯ごとの割込み処理時間をログに残します。この可視化は 4.3 の隠し要素「VDP MONITOR」として製品版にも残します。
